    ①b 大小写改名边界（Windows 两步法）

    Windows 上 readme.txt → Readme.txt 直接 rename 会报错（大小写不敏感文件系统认为是同名）。 方案：先改成临时名，再改回来。试一下：规则选「字符串替换」，查找 readme 替换为 Readme，勾选大小写敏感，预览 → 执行， 然后点历史记录看日志里的 case_only / via_tmp 字段；再撤销，撤销同样是两步。

    ② 操作日志 JSON 结构（提案）

    每次「执行修改」写一份日志到 %APPDATA%/rename-file/history/op_*.json，撤销=读最近一份未撤销日志逆向执行。删除/归档策略见下方决策点 4。

    {
  "version": 1,
  "op_id": "op_20260904_012345",
  "created_at": "2026-09-04T01:23:45+08:00",
  "base_dir": "D:/demo",
  "recursive": false,
  "rule": { "type": "regex", "params": { "find": "^IMG_", "replace": "2023_" }, "case_sensitive": true },
  "file_count": 2,
  "entries": [
    { "from": "IMG_0001.jpg", "to": "2023_0001.jpg", "status": "ok",
      "case_only": false, "via_tmp": null },
    { "from": "readme.txt", "to": "Readme.txt", "status": "ok",
      "case_only": true, "via_tmp": "__rename_tmp_op_20260904_012345_Readme.txt" }
  ],
  "undone": false,
  "undone_at": null,
  "undo_result": null
}

    撤销成功后写回："undone": true，"undo_result": { "restored": 2, "skipped": [ { "from": "...", "reason": "目标名已存在，跳过" } ] }。冲突文件绝不覆盖，只跳过并留痕。

    ③ CLI 交互（提案，与 GUI 共用同一个 core）

    $ rename-cli --dry-run --dir D:/photos --filter "*.jpg" --rule regex "^IMG_" "2023_"
  预览 12 条变更（--dry-run 不落盘、不写日志）
$ rename-cli --apply --dir D:/photos --rule regex "^IMG_" "2023_"
  已重命名 12 个文件，日志: %APPDATA%/rename-file/history/op_20260904_013020.json
$ rename-cli --undo                # 撤销最近一次
  已还原 12 个文件
$ rename-cli --undo --list         # 列出可撤销的操作栈

    ④ 待你拍板的决策点

    1. GUI 框架（最重要）现有代码是 wxPython（import wx），但子 Prompt #19 写的是「tkinter（不换框架）」，两者矛盾。A. 按 prompt 迁移 tkinter：零第三方依赖、exe 体积小，但要重写全部 UI；B. 保留 wxPython：改 prompt，UI 不动只加撤销。本原型的布局对两者通用。
    2. 撤销是否需要确认原型采用「先弹还原预览（标明每条 可还原/冲突跳过），点确认才执行」。也可以做成一键直接撤。
    3. 撤销深度Prompt 定的是保留最近 10 次可逐步回退。已撤销的日志是归档保留（可追溯）还是直接删除？原型按「归档保留、不再可撤」处理。
    4. 嵌套撤销的顺序严格按栈：只能撤最新一次，撤完才能撤上一次（原型如此）。要不要支持任意跳选某一次操作来撤？（不支持则实现简单、心智模型清晰）
    5. 日志目录%APPDATA%/rename-file/history/（提案，跨工作目录可用）还是放在操作目标目录里（随目录走，但会污染用户目录）？

    撤销预览：还原操作

    「冲突跳过」= 原文件名已被新文件占用。已跳过的条目不覆盖、不报错，留痕在 undo_result 里。
